# CodeSage 前端交互展示 Review

> 评审范围：src/main/resources/webui/（JCEF Web UI v2.x）
> 对照工具：Claude / Cursor / Copilot Chat / ChatGPT Canvas / Kimi / Windsurf / Continue.dev / Cody

详见下方分节分析。

## 一、当前实现概览（已做得不错的部分）

CodeSage Web UI 已经完成了从 v1 单文件到 v2 组件化、设计系统化的重构，具备以下基础能力：

| 维度 | 当前实现 |
|------|---------|
| 架构 | 原生 ESM + Web Components，无框架依赖，便于 JCEF 内联打包 |
| 设计系统 | `tokens.css` 统一管理颜色/间距/圆角/阴影，支持 light/dark/auto |
| 消息流 | 三栏布局（sidebar + chat + artifacts），内容最大宽 760px 居中 |
| 流式渲染 | append-only 分段渲染，按 `\n\n+` 切分段落，避免 O(n²) 重渲染 |
| 思考过程 | `cs-thinking` 折叠为单行 chip，running 显示呼吸点 + 计时，完成显示耗时 + tokens |
| 工具调用 | `cs-tool-call` 8 种 result kind，支持参数表格、命令 stdout/stderr、JSON、diff |
| 计划 | `cs-plan` 5 态步骤 + 进度条 + Approve/Reject/Modify |
| 代码块 | 语言徽标 + 复制按钮，高亮使用 highlight.js |
| 输入区 | 自动撑高 textarea、附件 chip、@文件引用、模式切换（Chat/Agent/Plan） |
| 交互细节 | 外部链接拦截、滚动锁定、快捷键、命令面板、Toast、模态框 |

**一句话评价**：地基扎实、工程化良好，但在"对话过程数据的叙事性呈现"和"现代 Agent UI 的精致感"上，与 2026 年主流工具存在明显代差。

---

## 二、核心差距分析

### 2.1 思考过程（Thinking / Reasoning）—— "可折叠的纯文本" vs "结构化推理地图"

**CodeSage 现状**：
- `cs-thinking.js` 把整个 thinking 流当纯文本塞入 `pre-wrap` 容器。
- 只有三种状态：running / completed / collapsed。
- 没有步骤拆分、没有高亮关键推理节点、没有让用户快速跳转到"它为什么选这个方案"。

**主流工具做法**：
- **Claude**：thinking 默认折叠，但展开后有段落感，长 thinking 带滚动，关键决策句加粗/列表化。
- **Kimi k1.6+**：thinking 以"推理树"或"步骤卡片"呈现，每个子问题独立可折叠。
- **ChatGPT o3/o4**：reasoning effort 可视化，thinking 过程用" bullet + 小标题"结构化。
- **Cursor Composer**：把 reasoning 和下一步计划混在一起，用 chip 形式 inline 呈现。

**差距**：
1. **纯文本无结构**：LLM 的 thinking 往往是"目标→分析→尝试→结论"的循环，CodeSage 没有提炼出这些阶段。
2. **无关键信息高亮**：无法一眼看到"模型意识到了什么错误""最终决定用什么工具"。
3. **无搜索/跳转**：长 thinking（几千 tokens）只能滚动，没有定位能力。
4. **与正文割裂**：thinking 和最终回答之间没有引用关系。

---

### 2.2 工具调用（Tool Calls）—— "卡片列表" vs "时间线 + 因果链"

**CodeSage 现状**：
- 每个 tool call 是一个独立折叠卡片，inline 插入到 cursor 之前。
- 卡片头部：状态图标 + 工具名 + summary + 耗时。
- 展开后：参数表格 + 结果（按 kind 渲染）。
- `delegate_task` 被隐藏，失败时才 toast。

**主流工具做法**：
- **Claude**：工具调用以"细线徽章"inline 显示在正文中，鼠标悬停展开详情，保持阅读连贯性。
- **Cursor Agent**：工具调用与文件变更强关联，读文件后可直接显示"查看差异"，改文件后 inline diff 预览。
- **GitHub Copilot Chat**：Agent mode 把工具调用串成时间线，每个步骤可点击展开文件/命令结果。
- **Windsurf Cascade**：工具调用和文件改动放在右侧 Cascade 面板，与左侧对话形成"请求-动作-结果"的因果链。

**差距**：
1. **卡片视觉过重**：每个工具都是带边框的独立卡片，多工具连续调用时屏幕被切碎，阅读正文被打断。
2. **缺少因果连接**：不知道"这个读文件是为了回答上一句哪个问题"，没有调用链/grouping。
3. **工具图标单一**：全部用 Font Awesome 通用图标，没有按工具语义分类（读文件、写文件、执行命令、搜索、MCP 等）。
4. **结果展示粗放**：
   - diff 结果只是纯文本转义，没有行号、没有 side-by-side、没有语法高亮。
   - 命令结果 stdout/stderr 只是两个 pre 块，没有折叠/搜索/复制单行。
   - 文件读取结果没有文件名 + 行号范围提示。
5. **缺少"应用到编辑器"的快捷入口**：虽然 artifact 有 apply，但 tool call 里的代码/diff 没有一键 apply/insert。
6. **并行工具无表达**：多个工具同时排队/运行时，没有统一的"批处理"视觉。

---

### 2.3 Plan / 任务计划 — "待办清单" vs "可交互执行图"

**CodeSage 现状**：
- `cs-plan.js` 是一个可折叠的 checklist：header 显示进度 + badge + 进度条。
- 步骤状态：pending / running / completed / failed / blocked。
- pending 时显示 Approve / Modify / Reject 按钮。

**主流工具做法**：
- **Claude Projects / Computer Use**：plan 以可编辑的 bullet list 呈现，每个步骤可点击"重新执行"，失败步骤高亮并给出重试/跳过选项。
- **Cursor Composer**：plan 和工具调用融合，每个步骤执行时会显示"当前在执行第 N 步"，步骤与文件变更绑定。
- **GitHub Copilot**：计划作为 agent loop 的顶层状态，用户可在任意步骤暂停、修改、继续。
- **Kimi**：长任务 planning 用树状或层级结构，子计划可嵌套展开。

**差距**：
1. **无依赖关系可视化**：`dependsOn` 字段在数据里有，但 UI 上没有任何连线/层级表达。
2. **Modify 按钮无反馈**：点击 Modify 只是发一个事件，没有提供 inline 编辑步骤的能力（如双击改文字、拖拽排序）。
3. **步骤与工具调用无关联**：执行到某一步时，对应的 tool call 没有高亮/锚点联动。
4. **没有历史回放**：无法看到"之前执行过几次 plan""哪一步失败了几次"。
5. **进度条太抽象**：对于复杂任务，单纯的 `done/total` 无法表达"关键路径完成了多少"。

---

### 2.4 代码块与 Artifacts — "可复制的高亮块" vs "可操作的代码产物"

**CodeSage 现状**：
- 代码块：语言徽标 + 复制按钮，hljs 高亮。
- Artifacts 面板：右侧 360px 折叠面板，显示生成的代码产物，支持复制/apply。
- `addArtifact` 在当前仓库中未找到调用点（注释也提到"addArtifact 在仓库中未被使用"）。

**主流工具做法**：
- **ChatGPT Canvas**：代码产物在独立画布中，可编辑、可运行（Python）、可版本对比、可一键 apply。
- **Claude Artifacts**：HTML/React/Python 等可直接预览运行，Artifact 有版本历史、可 fork。
- **Cursor Composer**：生成的代码修改直接在 diff 视图中展示，用户可逐行 accept/reject，apply 后有文件状态反馈。
- **Windsurf**：生成的文件改动汇总在右侧文件树，可批量 accept/reject，自动创建文件。

**差距**：
1. **Artifact 未启用**：代码产物能力已经实现但没有后端调用，等于不存在。
2. **代码块无版本对比**：模型修改代码时，无法看到"旧→新"的 diff。
3. **无文件上下文**：代码块没有显示它属于哪个文件、从第几行开始。
4. **无 Apply 反馈**：apply 后没有"已写入 src/xxx.kt"的成功/失败提示，也没有 diff 预览。
5. **无法运行/预览**：HTML/Markdown/Python 等没有预览能力。
6. **缺少"接受/拒绝"工作流**：用户不能对模型提议的修改做部分采纳。

---

### 2.5 输入区与上下文 — "带附件的文本框" vs "富上下文编排器"

**CodeSage 现状**：
- textarea 自动撑高，最多 8 行。
- 底部 toolbar：@引用、图片、发送按钮，中间模式 tab。
- 附件以 chip 形式展示在 textarea 上方。
- @文件引用通过文件选择器插入文本 `@relativePath`。

**主流工具做法**：
- **Cursor**：输入框支持 `@` 触发文件/符号/代码片段/文档的 autocomplete，带搜索高亮和预览；拖拽文件时显示大范围的 drop zone 动画。
- **Claude**：输入框支持拖拽文件生成附件 pill，@ 提及 Projects/Knowledge，粘贴图片自动处理。
- **GitHub Copilot**：`#file` `#selection` `#terminal` 等上下文变量有明确的 chip 和作用域提示。
- **ChatGPT**：输入框支持"记忆"、"自定义 GPT"、"代码解释器"等能力开关。

**差距**：
1. **无 @ 自动补全 UI**：虽然后端有 `file_search`，但输入框没有 autocomplete 下拉，用户必须记得文件名。
2. **拖拽反馈弱**：没有 drag-over 状态、没有 drop zone 高亮、没有"释放以上传"提示。
3. **上下文不可见**：用户不知道当前模型看到了哪些文件、多少 tokens、是否被截断。
4. **没有 prompt 模板/快捷指令**：welcome actions 只有 4 个静态按钮，不能自定义、不能搜索。
5. **模式切换太隐晦**：Chat/Agent/Plan 模式只是小 tab，没有解释差异，也没有根据用户输入自动建议模式。
6. **无语音输入**：主流桌面 AI 工具普遍支持语音输入或语音转文字。

---

### 2.6 对话流与状态感知 — "消息列表" vs "Agent 进程仪表盘"

**CodeSage 现状**：
- 每条 AI 消息是一个 turn，header 显示 CodeSage + 耗时 + 状态。
- 状态栏在输入区上方，显示"思考中…"等文字。
- 滚动策略：用户上滚后锁定自动滚，新 turn/新 tool 时强制滚动。

**主流工具做法**：
- **Cursor Composer**：顶部显示当前 agent 任务标题，左侧对话、右侧文件/命令/差异面板实时联动。
- **Windsurf Cascade**：顶部有"暂停/继续"、"步骤进度"、"tokens 消耗"等 Agent 仪表盘。
- **Claude**：长任务时显示"正在浏览网页""正在使用工具"等动态状态徽章。
- **GitHub Copilot Agent**：底部状态栏显示当前正在执行的工具、文件名、进度。

**差距**：
1. **缺少全局 Agent 状态**：用户不知道当前是在"思考""读文件""写文件""执行命令"还是"总结"。
2. **无 tokens/成本显示**：没有当前轮次或累计的 tokens、成本估算。
3. **无耗时细分**：只有 turn 总耗时，没有"思考耗时 / 工具耗时 / 生成耗时"拆分。
4. **滚动体验可优化**：长 thinking 默认折叠是对的，但新 tool 强制滚动可能打断用户回看。
5. **无"当前活动"指示器**：当 Agent 在后台执行长命令时，tab/icon 没有 badge 或动画提示。

---

### 2.7 视觉美感与品牌个性 — "干净但普通" vs "精致且有识别度"

**CodeSage 现状**：
- 颜色：Sage Emerald 强调色 + 中性灰阶，专业但保守。
- 圆角：小~中等圆角（4~12px），偏 IDE 工具感。
- 字体：Inter / JetBrains Mono，无自定义字体加载。
- 动画：简单 fade/slide/pulse，没有复杂的微交互。

**主流工具做法**：
- **Claude**：暖灰色调、柔和阴影、精致的 thinking 徽章、连贯的渐变 Mark。
- **Cursor**：深色主题下高对比紫/青强调、工具调用徽章非常克制、hover 反馈细腻。
- **ChatGPT**：干净但有很多细节：消息出现时的渐入、typing indicator 的流畅波浪、canvas 的独立视觉层级。
- **Kimi**：现代中文排版、卡片阴影克制但有层次、思考过程用细线分割。

**差距**：
1. **品牌识别度不足**：界面像"又一个 IDE 插件"，没有 CodeSage 独特的视觉签名。
2. **视觉层级偏平**：卡片与背景的对比度不够，在复杂对话中难以快速区分"这是文本""这是工具""这是计划"。
3. **微交互少**：hover、focus、加载、完成等状态的变化较生硬。
4. **图标系统单一**：全部依赖 Font Awesome，没有按语义设计的彩色/动态图标。
5. **暗色模式偏灰**：`surface-base: #1a1c1f` 仍偏亮，和 IDE 深色主题（通常 #0f0f10 ~ #18181b）有落差。

---

### 2.8 对话历史与管理 — "侧边栏列表" vs "可搜索、可分支的会话空间"

**CodeSage 现状**：
- 侧边栏 260px，默认折叠，按时间分组。
- 支持搜索、重命名、删除。
- 历史消息加载后会丢失 thinking/tool 的流式过程（`loadHistory` 中 thinking 直接 setContent，tool 直接 complete）。

**主流工具做法**：
- **Claude / ChatGPT**：支持对话分支（fork）、重新生成后保留多个版本、可对比。
- **Cursor**：每个 composer 会话独立，历史会话可搜索、可钉选。
- **Kimi**：支持会话内搜索、长对话自动摘要。

**差距**：
1. **无对话分支**：用户无法对某条消息做"从这里继续"或"重新生成并对比"。
2. **历史回放丢失过程**：重新加载后只看到最终结果，看不到当时的思考/工具执行过程。
3. **无会话内搜索**：长对话无法快速定位某条消息或代码块。
4. **侧边栏信息密度低**：除了标题没有预览、没有标签、没有会话长度/模型信息。

## 三、高优先级改进建议

### P0 — 对话过程数据呈现（立即投入）

#### 1. 重构 Thinking 展示：从纯文本到结构化推理
- **阶段化解析**：后端或前端对 thinking 文本做轻量解析，识别 `"## 分析"` `"## 尝试"` `"## 结论"` 等结构，渲染成折叠段落。
- **关键句高亮**：对 `"所以"` `"因此"` `"错误"` `"修正"` `"决定"` 等关键词加语义高亮或图标。
- **与正文联动**：最终回答中若引用 thinking 中的某一步，支持 hover 显示原文片段。
- **持久化展开状态**：用户展开某段 thinking 后，后续同 session 保持展开偏好。

#### 2. 工具调用视觉降级 + 语义升级
- **轻量徽章**：running 状态用 inline 小徽章（如 `🔍 Reading src/main.kt`）替代完整卡片，完成后再折叠为单行。
- **工具图标映射**：为常用工具设计专属图标/颜色：
  - 读文件 → 📄 蓝色
  - 写文件/编辑 → ✏️ 绿色
  - 执行命令 → ⚡ 黄色
  - 搜索 → 🔍 紫色
  - MCP → 🔌 橙色
- **工具链分组**：同一轮次中连续调用的工具可折叠为"已执行 5 个工具"的汇总条，点击展开。
- **diff 结果增强**：用行号 + 红绿背景 + side-by-side 选项，支持 apply/reject。

#### 3. Plan 与 Tool Calls 联动
- 每个 plan step 点击后滚动/高亮对应的 tool call。
- step 完成时显示"耗时 + 对应工具"的 tooltip。
- 增加"重试失败步骤""跳过步骤"按钮。

---

### P1 — 代码/产物工作流（1~2 个迭代）

#### 4. 启用并升级 Artifacts
- 后端接入 `addArtifact`，让代码生成真正进入右侧面板。
- Artifact 支持多 tab、版本历史、diff 对比。
- 对 HTML/Markdown/Python 提供预览/运行能力。
- Apply 后显示文件状态："已创建 src/xxx.kt" / "已修改 3 处"。

#### 5. 消息内代码块增强
- 代码块显示文件路径和行号范围。
- 代码块增加"Apply to Editor""Insert at Cursor""Create File"按钮。
- 模型修改代码时，优先以 diff 块展示，而不是整段重写。

---

### P1 — 输入与上下文（1~2 个迭代）

#### 6. @ 提及自动补全
- 输入 `@` 触发文件/符号搜索下拉，显示文件路径、最近打开、当前选中代码。
- 支持 `#selection` `#terminal` `#git` 等上下文变量。

#### 7. 上下文可视化
- 在输入区上方或 sidebar 显示"当前上下文"：已引用文件、图片、tokens 估算。
- 发送前提示"上下文可能过长，建议精简"。

#### 8. 拖拽/粘贴增强
- 拖拽文件到输入区时显示全局 drop zone 动画。
- 粘贴图片后立即在输入区展示大图预览。

---

### P2 — 视觉与体验打磨（持续）

#### 9. Agent 状态仪表盘
- header 或输入区上方增加 mini 仪表盘：当前阶段（思考/读/写/执行/生成）、本轮 tokens、总耗时。
- 长任务时支持"后台运行"，完成后 toast 提醒。

#### 10. 对话分支与历史回放
- 对每条 AI 消息支持"重新生成"后保留多个版本，可切换对比。
- 历史加载时保留 thinking/tool 的时序（后端需持久化这些事件）。

#### 11. 视觉升级
- 为工具/计划/思考设计专属图标和颜色体系。
- 引入更细腻的阴影和过渡动画。
- 暗色模式进一步压暗，贴近 IDE 深色主题。
- 增加品牌微动画（如 thinking 时的 brain icon 脉冲）。

---

### P2 — 可访问性与工程（持续）

#### 12. 无障碍增强
- 所有折叠卡片支持正确的 `aria-expanded` / `aria-controls`。
- 流式内容更新时通过 `aria-live` 提示屏幕阅读器用户。
- 减少动画模式下保持功能可用。

#### 13. 性能
- 长对话引入虚拟滚动（当前所有消息都在 DOM 中）。
- 超大工具结果支持虚拟化或分页。

---

## 四、推荐实施路线

### 第一阶段（2 周）：对话过程数据呈现重塑
1. `cs-thinking` 结构化：增加段落解析 + 关键句高亮。
2. `cs-tool-call` 视觉降级：running 变 inline badge，完成折叠为单行。
3. 工具图标映射 + diff 增强。
4. Plan 与 Tool 联动高亮。

### 第二阶段（2 周）：代码产物工作流
1. 后端接入 `addArtifact`，前端升级 Artifact 多 tab + diff。
2. 代码块增加 Apply/Insert/Create File 按钮。
3. diff 结果 side-by-side 视图。

### 第三阶段（2 周）：输入与上下文
1. @ 提及自动补全 UI。
2. 上下文可视化条。
3. 拖拽/粘贴反馈升级。

### 第四阶段（持续）：视觉与高级功能
1. Agent 仪表盘。
2. 对话分支与历史回放。
3. 虚拟滚动 + 性能优化。
4. 品牌视觉升级。

---

## 五、结论

CodeSage 的前端在工程层面已经相当成熟：组件化、设计系统、事件协议、主题切换、错误边界都具备生产级质量。但当前界面仍然停留在"更好的聊天窗口"层面，而 2026 年的主流 Agent 工具已经进化到"**Agent 进程仪表盘 + 代码产物工作坊 + 上下文编排器**"的三位一体形态。

**最关键的 3 个突破口**：
1. **把工具调用从"卡片列表"变成"轻量时间线"**，减少视觉噪音，强化因果链。
2. **把思考过程从"纯文本折叠"变成"结构化推理地图"**，提升可解释性。
3. **把代码产物从"可复制代码块"变成"可应用、可对比、可预览的工作流"**，真正闭环编码任务。

这三个方向如果能落地，CodeSage 的前端体验会从"可用"跃迁到"好用且好看"，显著缩小与 Cursor/Claude/Windsurf 等头部产品的差距。
