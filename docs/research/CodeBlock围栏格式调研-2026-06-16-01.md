## 2. CommonMark 围栏核心规范(权威)

来自 [CommonMark 0.31.2 §4.5](https://spec.commonmark.org/0.31.2/#fenced-code-blocks):

### 2.1 围栏字符

- **类型 1**:`` ` ``(反引号,U+0060)
- **类型 2**:`~`(波浪号,U+007E)
- 两种**不能混用**

### 2.2 围栏长度

- 至少 **3 个**连续字符
- 可以更长(4、5 个...也是合法的)

### 2.3 闭合围栏规则

- 必须与开围栏**同类型**
- **长度 ≥ 开围栏长度**(可以更长)
- 前可有 0-3 空格缩进
- 后只能跟空格/tab(忽略)
- **可省略**:文件/块结束 = 代码块结束(CommonMark 允许不闭合)

### 2.4 info string(开围栏后的文本)

- 前后空格/tab 被 trim
- **反引号围栏后不能含反引号字符**(否则 inline code 解析歧义)
- 第一个词通常用作 language(class=`language-xxx`)

### 2.5 缩进处理

- 开围栏前可有 0-3 空格缩进
- 内容行如果缩进 ≤ 开围栏缩进,缩进被剥离
- 例:开围栏缩进 2 空格,内容行缩进 1 或 2 空格都被剥离;缩进 3+ 空格保留

### 2.6 段落中断

- 代码块**可以**中断段落,前后不需要空行

### 2.7 嵌套

- 围栏代码块**不支持嵌套** —— 内层围栏字符只是字面量

## 3. 各 LLM Provider 围栏格式

### 3.1 OpenAI 系(GPT-4 / o1 / DeepSeek / Kimi / MiniMax)

**结论**:全部使用标准 CommonMark 围栏(`` ``` `` + lang)。

| 模型 | 围栏字符 | lang 标识 | 路径信息 | 备注 |
|------|---------|----------|---------|------|
| GPT-4 / o1 | `` ``` `` | `python` / `javascript` / `kotlin` 等 | **不**带 | 标准 |
| DeepSeek | `` ``` `` | `python` 等 | **不**带 | 标准 |
| Kimi | `` ``` `` | `python` 等 | **不**带 | 标准 |
| MiniMax-M3 | `` ``` `` | `python` 等 | **不**带 | 标准(本仓库 MiniMaxAdapter 是 OpenAICompatible 子类) |

**实测**(基于本仓库 MiniMaxAdapter first-chunk dump 日志):
```
content.head=<think>The user is asking me...   ← MiniMax 推理格式
```

MiniMax-M3 的流式 content 是普通 markdown 文本(无专用 reasoning 字段),围栏是标准 `` ``` ``。

### 3.2 Anthropic Claude

**结论**:**根本不发围栏字符串**!Claude API 协议本身是结构化的 `content_block_*` 事件:

```json
// 来自 Anthropic Messages API streaming
{"type":"content_block_start","content_block":{"type":"tool_use",...}}
{"type":"content_block_delta","delta":{"type":"input_json_delta","partial_json":"..."}}
{"type":"content_block_stop"}
```

**Anthropic 不需要 adapter 层做围栏解析** —— `content_block_start/delta/stop` 可以**直接**透传为 `CodeBlockStart/Delta/End` 事件,无歧义。

(注:Claude Web UI 显示的 `` ``` `` 是前端展示用的,API 本身没有。)

### 3.3 Gemini

**结论**:使用标准 CommonMark 围栏(`` ``` `` + lang),与 OpenAI 系一致。

### 3.4 GPT-4 / o1(特殊性)

- 标准 `` ``` `` 围栏
- **可能**在 thinking 模式下混用 reasoning 字段(类似 MiniMax)
- CodeBlock 解析与 reasoning 解析互斥(优先级 reasoning > codeBlock > text)

## 4. 生产环境数据采样

扫描 `~/.codesage/conversations/*.json` 共 **1232 个会话**:

```
含 `` 围栏的 assistant.content: 0
```

**结论**:生产环境中,所有 assistant 持久化的 content **都不含围栏**。

可能原因(待验证):
1. 用户从未触发"让模型写代码"的对话(测试都是普通问答)
2. 后端在持久化前过滤了围栏
3. 模型响应中代码块以其他方式表达(比如纯文本带行号)

**本次重构的影响**:
- 新 CodeBlock 事件驱动后,assistant.content **会**包含围栏(因为现在从 `chunk.delta` 切走代码块字符,代码块字符不再进 `assistantContent`)
- 也就是说重构后,持久化数据会**新增**围栏内容,这是预期行为(让会话回放能恢复代码块结构)

## 5. 流式场景下的边界行为

### 5.1 围栏跨 chunk 拆分(关键)

LLM 流式响应把围栏字符串**任意切分**到多个 chunk,常见切分点:

```
chunk_1: "```"
chunk_2: "kotlin\nfun main()"
chunk_3: "() { println"
chunk_4: "(\"hi\") }\n```"
chunk_5: "\nDone"
```

**适配器必须跨 chunk 累积围栏识别状态**。已有 `splitThinkTag` 状态机可作参考。

### 5.2 info string 跨 chunk 拆分

```
chunk_1: "``"          (围栏不完整)
chunk_2: "`kotlin\n"   (补全围栏 + 给出 lang)
```

需要累积 buffer 来判断"何时围栏字符序列达到 3 个"。

### 5.3 多个代码块(并行/串行)

```
chunk_1: "```kotlin\nfun a() {}\n```\n"
chunk_2: "```python\ndef b():\n"
chunk_3: "    pass\n```\n"
chunk_3: "```java\nclass C {}\n```"
```

需要 `codeBlockCounter` 累加 + `currentCodeBlockId` 切换。

### 5.4 不闭合的围栏

```
chunk_1: "```kotlin\nfun a() {\n"
chunk_2: "    println(\"hi\")\n"   ← 没有闭合围栏
[stream ends]
```

按 CommonMark 规范,流结束时未闭合 = 整个剩余内容是代码块。

**适配器处理**:`done=true` 时如果 `inCodeBlock=true`,自动 emit `CodeBlockEnd`。

### 5.5 嵌套场景(围栏字符在内容中)

```
chunk: "```markdown\n# Example\n```python\nprint(1)\n```\n```\n"
```

外层 ```` ```markdown `` 围住的内容里,有内层 ```` ```python `` 字符串 —— **这不构成嵌套**,按外层围栏走,内层反引号是字面量。

适配器状态机:在 inCodeBlock=true 时,看到的 ```` ``` ``**长度 ≥ 开围栏长度**才闭合,否则视为字面量。

### 5.6 tilde 围栏(`~~~`)

CommonMark 规范允许 `~~~` 作为围栏字符。**实际 LLM 极少使用**,但理论上 Anthropic / OpenAI 不会主动发,如果遇到应该按规范识别。

**本次重构**:**支持** tilde 围栏识别(规则同 backtick,只是字符换成 `~`)。

### 5.7 4 个反引号(`` ```` ``)

CommonMark 允许,用于"代码块里再含 `` ``` `` 代码块"的场景。本项目前端 markdown-it 14.1.0 完全支持。

**本次重构**:**支持**任意长度(≥3)的反引号围栏。

### 5.8 围栏内有空行

```
chunk: "```kotlin\n\nfun a() {}\n\n```\n"
```

完全合法,空行是代码块内容的一部分。

### 5.9 行首/行尾空白

```
chunk: "   ```kotlin   \n"   ← 围栏前后空格
```

按 CommonMark:开围栏前 0-3 空格缩进允许;info string 前后空格被 trim。

**本次重构**:**支持** 0-3 空格缩进。

## 6. 支持范围决策

基于以上调研,本次 CodeBlock 事件驱动重构的**支持范围**如下:

### 6.1 ✅ 必须支持

| 场景 | 状态机处理 |
|------|----------|
| 标准 `` ``` `` 3 反引号 | ✅ |
| `~~~` 3 波浪号 | ✅ |
| 任意长度(≥3)的反引号/波浪号 | ✅ |
| info string(空 / lang / lang + 路径) | ✅ |
| 围栏前 0-3 空格缩进 | ✅ |
| 跨 chunk 累积(围栏字符序列) | ✅ |
| 多个代码块(codeBlockCounter 累加) | ✅ |
| 流结束时未闭合 → 自动 CodeBlockEnd | ✅ |
| tilde vs backtick 区分(同类型闭合) | ✅ |
| 闭合围栏长度 ≥ 开围栏长度 | ✅ |

### 6.2 ⚠️ 部分支持(后续可补)

| 场景 | 处理 |
|------|------|
| info string 含空格(隐含文件路径) | **保留完整字符串**,解析为 `language + 剩余路径` 由前端二次处理 |
| 4+ 反引号嵌套 | ✅ 状态机通用,无特殊处理 |
| 围栏内有 thinking 段 | **不处理** —— `splitThinkTag` 优先,reasoning 段切走后代码块字符进 `chunk.delta` |

### 6.3 ❌ 暂不支持(fallback 到原 rawText 走 markdown-it 渲染)

| 场景 | 处理 |
|------|------|
| 围栏字符出现在 inline code 里(`` ` `` 单个) | **不构成围栏**;状态机只看 ≥ 3 连续字符 |
| 围栏字符前后有 4+ 空格缩进 | 按 CommonMark 是 HTML block,本次**不**识别(LLM 不会用) |
| 围栏紧接段落首字符(无换行) | 按 CommonMark 是合法,但**要求开围栏是单独一行** —— LLM 实际不会这么发,**忽略** |

### 6.4 不发送 CodeBlock 事件的场景

| 场景 | 走 TextDelta |
|------|------------|
| 单反引号 inline code | 走 TextDelta(由前端 markdown-it 渲染) |
| 行内 `` `text` `` | 走 TextDelta |
| 不闭合的围栏但流正常结束(已 emit CodeBlockEnd) | 后续字符走 TextDelta |
| 模型使用 4+ 反引号但状态机错误识别为 3 个 | 走 TextDelta(等错误反馈再补) |

## 7. 状态机设计草案

### 7.1 状态变量

```kotlin
private var inCodeBlock: Boolean = false
private var currentCodeBlockId: String? = null
private var currentCodeLang: String? = null
private var currentFenceChar: Char? = null       // '`' or '~'
private var currentFenceLength: Int = 0
private var pendingFence: StringBuilder = StringBuilder()  // 累积围栏字符序列
private var pendingCode: StringBuilder = StringBuilder()    // 累积代码内容
private var codeBlockCounter: Int = 0
```

### 7.2 状态机步骤(伪代码)

```kotlin
// 在 parseStreamChunk 内,对 rawDelta 应用状态机

fun processFencedCode(rawDelta: String): FencedCodeResult {
    val emittedEvents = mutableListOf<CodeBlockEvent>()
    var remaining = rawDelta
    
    while (remaining.isNotEmpty()) {
        if (!inCodeBlock) {
            // 状态 1: 不在代码块内
            // 找开围栏: 同一行有 ≥3 个连续 ` 或 ~,前面是 0-3 空格,后面跟行尾或空格+info string
            val openMatch = findOpeningFence(remaining)
            if (openMatch != null) {
                // 输出开围栏之前的字符为 text (emit TextDelta)
                if (openMatch.textBefore.isNotEmpty()) {
                    emittedEvents.add(TextDelta(openMatch.textBefore))
                }
                inCodeBlock = true
                currentCodeBlockId = "cb-${++codeBlockCounter}"
                currentFenceChar = openMatch.fenceChar
                currentFenceLength = openMatch.fenceLength
                currentCodeLang = openMatch.infoString.takeIf { it.isNotBlank() }
                emittedEvents.add(CodeBlockStart(currentCodeBlockId!!, currentCodeLang))
                remaining = openMatch.rest
            } else {
                // 没有开围栏,整段作为 text
                emittedEvents.add(TextDelta(remaining))
                remaining = ""
            }
        } else {
            // 状态 2: 在代码块内
            // 找闭围栏: 同一行有 ≥currentFenceLength 个 currentFenceChar,后面只能跟空白
            val closeMatch = findClosingFence(remaining)
            if (closeMatch != null) {
                // 输出闭围栏之前的代码内容
                if (closeMatch.contentBefore.isNotEmpty()) {
                    emittedEvents.add(CodeBlockDelta(currentCodeBlockId!!, closeMatch.contentBefore))
                }
                // emit CodeBlockEnd
                emittedEvents.add(CodeBlockEnd(currentCodeBlockId!!))
                inCodeBlock = false
                currentCodeBlockId = null
                currentFenceChar = null
                currentFenceLength = 0
                currentCodeLang = null
                remaining = closeMatch.rest
            } else {
                // 没有闭围栏,整段作为代码内容(等下一个 chunk)
                emittedEvents.add(CodeBlockDelta(currentCodeBlockId!!, remaining))
                remaining = ""
            }
        }
    }
    
    return emittedEvents
}
```

### 7.3 done 兜底

```kotlin
// 跟 splitThinkTag 一样,在 parseStreamChunk 末尾:
if (inCodeBlock) {
    events.add(CodeBlockEnd(currentCodeBlockId!!))
    inCodeBlock = false
    currentCodeBlockId = null
}
```

### 7.4 跟 splitThinkTag 的关系

两个状态机**独立**:
- `inThinkBlock` 优先(`<think>` 切走)
- `inCodeBlock` 在 `inThinkBlock=false` 时跑
- 互不影响

### 7.5 resetStreamState 重置

```kotlin
fun resetStreamState() {
    inThinkBlock = false
    pendingThink.setLength(0)
    // 新增:
    inCodeBlock = false
    currentCodeBlockId = null
    currentCodeLang = null
    currentFenceChar = null
    currentFenceLength = 0
    pendingFence.setLength(0)
    pendingCode.setLength(0)
    codeBlockCounter = 0
}
```
